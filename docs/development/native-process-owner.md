# Internal native process owner

`internal/runtime/processowner` provides terminal descendant cleanup for one dedicated, unprivileged Linux AMD64 or ARM64 host. It is an internal prerequisite for a runtime transport that can stop its writers before workspace export. It is not connected to the worker, does not issue export or teardown authority, and is not installed in a published runtime candidate.

The host must start with no children and create its only native entry point through `Owner.Start`. It must never install another child-signal handler or child waiter, spawn a process through another API, or share ownership with a server or worker. The trusted host selects the fixed executable, arguments and environment. Native standard input, output and diagnostic pipes remain separate from any trusted host control transport. A failed construction can leave irreversible process protections installed; the host must exit.

Construction rejects root, mismatched real/effective/saved identities, nonzero effective, permitted, inheritable or ambient capabilities and existing children. It requires procfs, disables host dumpability and enables Linux child-subreaper adoption. The native child cannot read the host's memory or reopen its control descriptors through procfs. A fixed inherited seccomp filter rejects `CLONE_PARENT`, returns `ENOSYS` for `clone3`, rejects alternate syscall ABIs and denies ptrace and cross-process memory writes. The filter is installed on the locked spawning thread before fork and is inherited across native fork and exec. Ordinary threads, forks, detached sessions and descendants remain supported.

The pinned OpenShell policy remains the filesystem, network and syscall enforcement boundary. This owner uses current-thread `prctl` filter installation; it does not require the pidfd operations or `seccomp` filter-installation syscall denied by that policy. It is not a Cedar compiler and cannot replace OpenShell enforcement. Deployment must exclude other workspace writers and paths that transfer writable handles or execution to processes outside this ancestry.

`Owner.Stop` permanently seals starts and closes native input. It enumerates direct children across the host's threads, checks their parent identity and signals them before it reaps any child. The host is the sole waiter and retains exited children as zombies during that signal pass, so their PIDs cannot be reused. Detached and orphaned descendants are adopted and processed on subsequent passes. Waiting includes clone children that do not use `SIGCHLD`. Success requires the kernel to report `ECHILD`, with no remaining descendants. Cleanup has a 30-second bound or the caller's earlier deadline. Cancellation or failure remains unconfirmed and sealed; a later stop can retry. Completed stop replay is read-only.

A host crash, lost control acknowledgement or failed stop supplies no quiescence proof. A future caller must preserve the workspace in those cases. Process cleanup alone does not establish filesystem durability, authorize capture, retain a change artifact or permit sandbox deletion. An exact accepted image contract, durable lifecycle integration and export-before-teardown recovery remain separate work. The opt-in framed transport below supplies a private terminal exchange for development verification.

## Verification

Linux tests run each owner in a separate unprivileged process. They cover detached and orphaned descendants, concurrent forks, non-`SIGCHLD` children, ordinary threads, concurrent stops, cancelled-stop recovery, failed native start, empty stop, duplicate construction, copied owner state and starts, inherited ancestry restrictions, host memory and descriptor access denial, and survival of an unrelated sibling. Unsupported platforms fail closed.

The strict supervisor workflow adds the test binary to an unpublished fixture and selects `DATAGROUND_TEST_PROCESS_OWNER_REQUIRED=true` with the strict workspace-change profile. It runs the adversarial cases through the real gateway under the additional native workspace policy, rejects skipped results, and retains the existing credential, source and export checks. That evidence covers the tested kernel and policy composition; it is not operational or release acceptance. No independent acceptance authority is configured by these tests.

## Opt-in native host transport

`cmd/dataground-native-owner` is a dedicated host for the existing `/usr/bin/codex app-server` launcher. It accepts no command arguments or client-selected executable, environment or working directory. `Provider.StartOwnedRuntime` selects this fixed helper for the same exact sandbox lookup as the existing transport. The default `StartRuntime` and worker composition remain unchanged. Installation in an accepted owner-capable image and exclusion of all other workspace writers are caller prerequisites.

The internal `dataground.native-owner/v1` exchange uses bounded binary frames on one private SSH session. A fresh 32-byte controller nonce binds the ready and terminal acknowledgements to that connection. Native input, output and diagnostics occupy separate frame types; native bytes cannot become host control messages. Frames are limited to 64 KiB and pending native input to eight frames. Input overload fails the exchange rather than growing memory or silently dropping bytes. Invalid, duplicated, out-of-order or oversized control data fails closed. The handshake has a 15-second bound. No native process starts before a valid handshake.

`Owner.Wait` records native entry-point exit under the same lock used by terminal cleanup. Native exit is distinct from descendant cleanup and can leave detached writers alive. Waiting never reaps a child during a terminal signal pass. The client exposes a stable native-exit result through the existing private runtime-session interface.

`Session.Quiesce` permanently seals native input and drains remaining native output, so the caller must finish processing required native data before requesting it. The quiesce frame must be the final controller input, followed by EOF. The host requires successful descendant cleanup, native exit observation and complete native output and diagnostic closure before sending the exact nonce back. The client additionally requires complete framed output, empty host diagnostics and successful host exit. Missing acknowledgement, malformed output, cancellation, failed cleanup or failed host exit remains unconfirmed. Completed exact replay is read-only; the process-local result cannot be serialized as a certificate. `Close` attempts this terminal exchange but a failed close provides no proof.

The host bounds terminal cleanup and stream drain to 35 seconds; the client bounds the complete terminal exchange to 40 seconds or its caller's earlier deadline. Lost transport triggers best-effort host cleanup without creating a controller-side acknowledgement. It cannot be recovered by opening another runtime or starting another native turn. The caller must preserve the workspace until a separately authorized recovery or retention decision resolves the unconfirmed state.

Protocol tests cover native control-message forgery, missing or substituted acknowledgements, extra frames, incomplete stream closure, host failure, nonempty host diagnostics, cancellation, concurrent terminal requests, abandoned output consumers, native-exit replay and serialization denial. The strict gateway fixture runs Codex through this owner, proves that a detached descendant continues writing after its original command ends, then requires terminal acknowledgement and successful host exit before exporting and reconstructing its final binary changes twice. This is development evidence for that exact composition. Durable worker binding, export authorization, accepted image publication, retained completion and `termination_blocked` integration are still required before the worker can use it for teardown.
