# Runtime output and invocation results

The internal adapter contract distinguishes streamed text previews from completed message snapshots. `output.text.delta` remains a display event. The governed worker limits each delta to 64 KiB of UTF-8, escapes NUL as `\u0000`, and truncates that display preview to the same byte limit after escaping. `output.message.completed` carries exactly `text` and `phase`, where phase is `commentary`, `final`, or `unspecified`. Native completed snapshots are bounded to 1 MiB of UTF-8 text. The public inline message remains bounded to 64 KiB; snapshots whose encoded payload exceeds 128 KiB also use artifact storage. Messages containing NUL use artifact storage at any size. A structured message also uses an artifact if decoding its JSON creates NUL in a string value or object key. Native routing identifiers and memory-citation metadata do not cross this boundary. These events use the existing `dataground.event/v1` envelope; the new event type is additive.

The governed worker records each event through the current invocation claim before observing its result content. It selects the completed non-commentary message with the highest runtime source sequence. A later completed message replaces the prior candidate; messages are never concatenated. An unspecified phase permits the last completed answer from a runtime or model that does not classify phases. It is not relabelled as explicitly final. Commentary and text deltas remain in the event journal, but are not result candidates. Replayed source sequences do not change selection.

After successful native completion, the worker validates the selected text against the declared output schema. A text-producing turn without a completed answer fails with the existing `RUNTIME_OUTPUT_INVALID` receipt. A structured result also requires a nonempty completed answer and exactly one JSON value. A turn with no text events and no declared schema can still complete with an empty text result. The worker accepts at most 4,096 completed messages and retains its existing encoded-result limit. Invalid results cannot enter success artifact finalization. The successful attempt receipt stores the validated result, so a replacement worker can recover it without native execution. An interrupted or failed turn cannot use a completed message to bypass its terminal outcome.

When a completed answer fails validation, the worker first fixes its journal source sequence, artifact identity, digest, and byte count in an `output_invalid` runtime attempt. It then checks current authorization and readiness and renews the claim. For an inline answer, it retains the exact completed text as a sensitive `text/plain; charset=utf-8` artifact named `Invalid runtime result`. For an artifact-backed answer, it reuses the exact existing catalog binding. It commits the terminal `RUNTIME_OUTPUT_INVALID` receipt only after that exact artifact has a catalog binding. This path does not export declared workspace artifacts. A missing completed answer still fails without a result artifact because no acknowledged result exists.

Object or catalog failures leave the retention intent pending. A replacement worker can adopt it under its current lease and repeat immutable finalization without starting a runtime. New runtime events cannot change the fixed source; exact event replay remains read-only. A changed source, artifact substitution, expired or stale lease, foreign domain, cancellation, or current authorization denial prevents new publication. Cancellation can leave a pending intent for operator inspection; it does not grant retention authority. Database migration 61 refuses downgrade while any pending retention intent exists. The internal source sequence is stored as a decimal string to preserve all PostgreSQL sequence values through JSON decoding. The raw result remains subject to the 1 MiB completed-snapshot limit and the deployment's artifact-size limit. An invalid result whose snapshot is already stored reuses that artifact; it does not write a second copy. Migration 62 extends pending retention to the snapshot limit and rejects downgrade while a larger pending intent exists.

Completed snapshots that require artifact storage are finalized as sensitive UTF-8 text artifacts under the current claim, authorization, and readiness checks. The public `output.message.artifact` event contains only `artifactId`, `digest`, `sizeBytes`, `phase`, and a UTF-8-safe preview of at most 1,024 bytes. NUL appears as `\u0000` in the preview because PostgreSQL JSONB cannot store that character; the artifact retains the original bytes. Its artifact identity includes the isolation domain, invocation, and runtime source sequence. The journal verifies the exact catalog binding before accepting the reference. A native adapter cannot supply this event directly. Commentary artifacts remain progress only; a later completed answer replaces the earlier result candidate.

The worker validates the complete original snapshot before returning `dataground.invocation-artifact-result/v1`. This result contains `status: succeeded` and an `outputArtifact` reference with the artifact ID, digest, size, and media type. It does not return the full value inline. Completion verifies the reference against the latest non-commentary source and a successful native terminal event. A committed result survives worker replacement without repeating native execution. The Workbench exposes an inspect action after an explicit result read, and checks that the artifact belongs to the invocation before navigation. Inspection first loads artifact metadata. An explicit Workbench content read then verifies the complete size and digest before it displays text or enables a byte-exact download through the separately configured [artifact-content API](artifact-content.md). This remains durable loopback development mode.

Artifact publication does not establish native completion. If storage or journal acknowledgement fails before a successful runtime receipt is committed, the single-use native attempt remains ambiguous; a replacement does not rerun it. A retained artifact alone cannot prove a successful turn. Immutable finalization observes object writes before repetition, including lost write acknowledgements. This boundary does not add recovery of an unacknowledged native turn.

The pinned Codex 0.117.0 protocol supplies authoritative text through `item/completed` with an `agentMessage` item. Its `commentary` and `final_answer` phases map to the normalized phases; null or omitted phase maps to `unspecified`. The adapter rejects malformed content, unknown phase values, foreign thread or turn scope, oversized text, and a changed completion for an already completed native item. Exact duplicates are ignored. The private completed-item ledger is bounded to 4,096 entries; identifiers are bounded to 1,024 bytes. Late item notifications cannot change a terminal turn. See the [official app-server documentation](https://learn.chatgpt.com/docs/app-server) and the [schema at the pinned source revision](https://github.com/openai/codex/blob/4c70bff480af37b1bf1a9b352b8341060fe55755/codex-rs/app-server-protocol/schema/json/v2/ItemCompletedNotification.json).

The shared adapter kit covers completed commentary, unspecified and final messages, native duplicate completion, and authoritative text that differs from its preview. Focused worker tests cover schema validation, source ordering, replay, missing answers, malformed payloads, and bounded message count. PostgreSQL integration tests cover completed-result recovery, invalid-result retention after catalog outages and lost acknowledgements, immutable source binding, artifact substitution, cancellation, and stale or foreign claims. The timeline displays progress messages and final answers without implying invocation success.

This remains the internal governed invocation boundary. Production artifact delivery, artifact storage for images, public multi-turn sessions, and certification of every runtime family remain separate release work. Passing these tests does not certify a runtime deployment or establish v1.0 acceptance.

## Completed command output

Codex 0.117.0 supplies the final combined stdout/stderr snapshot in the optional `aggregatedOutput` field of a completed `commandExecution` item. The adapter preserves that exact UTF-8 snapshot, including empty output, with a 1 MiB limit. It maps `declined` to `denied` and preserves `completed`, `failed`, and the optional signed 32-bit exit code. Missing or null output produces no content artifact and is explicitly marked unavailable in the process-completion event. A command outcome does not establish the outcome of its containing turn or invocation.

The internal `output.command.completed` snapshot never enters the public journal. The governed worker retains it as a sensitive `text/plain; charset=utf-8` log named `Completed command output`, with the same current authorization, readiness, lease and immutable finalization boundaries used for completed answers. Its identity binds the isolation domain, invocation and source sequence in a separate command namespace. The additive public `output.command.artifact` event contains exactly `artifactId`, `digest`, `sizeBytes`, `status`, `exitCode` and a UTF-8-safe preview of at most 1,024 bytes. NUL is shown as `\u0000` in the preview because PostgreSQL JSONB cannot store that character; the artifact bytes remain exact. The journal checks its exact catalog, operation, effect, digest and size binding under the current claim. Native adapters cannot supply public artifact references. The Workbench offers artifact inspection and the separately authorized verified content read; previews remain untrusted text.

Command strings, working directories, process identifiers and native item identifiers are not copied into public metadata. Output content can contain sensitive data and remains governed content, including its bounded preview. Exact duplicate native completions are suppressed; changed output, status, exit code or availability for the same native item fails closed. This private command ledger is bounded to 4,096 items. Command output never replaces the completed assistant answer or bypasses output-schema validation. Persisted success can be settled after worker replacement without repeating execution; storage or journal failure before a terminal receipt remains an ambiguous native attempt. Output beyond the snapshot limit fails closed, and streamed command deltas are not reconstructed into a purported final snapshot.

## Completed file patches

Completed Codex `fileChange` items are retained as `dataground.runtime-patch/v1` JSON artifacts. The snapshot preserves native change order, exact diff text, `add`, `delete` or `update` kind, and optional move target. Paths are canonical names relative to the requested working directory or the directory reported by `thread/start`; a reported directory must match an explicitly requested directory. Missing root context, foreign absolute paths, traversal, malformed paths, unsupported kinds and malformed moves fail closed. These names describe the snapshot. They do not grant filesystem access or authorize application of a patch. Diff text is untrusted governed content and can itself contain paths or sensitive text.

The adapter maps `declined` to `denied` and preserves `completed` and `failed`. It emits `activity.file.completed` with the outcome and change count. Empty native change sets have no content to retain. Nonempty sets produce an internal `output.patch.completed` snapshot with at most 256 changes and 1 MiB of canonical encoded JSON. A bounded private ledger suppresses exact native completion replay and rejects changed replay. Native item identifiers, working-directory roots and paths do not enter public event metadata.

The worker retains the JSON as a sensitive `application/json` structured-output artifact named `Completed file patch` under the shared authorization, readiness and lease checks. Its deterministic identity includes the domain, invocation and runtime source sequence in a separate patch namespace. The public `output.patch.artifact` event contains only `artifactId`, `digest`, `sizeBytes`, `status`, `changeCount` and a fixed bounded summary. The journal requires its exact catalog binding and rejects raw patch snapshots. The Workbench exposes inspection and the existing explicit verified content read. It displays failed and denied file changes without claiming invocation success. A retained failed or denied patch is evidence of the reported attempt, not proof that its changes were applied.

Patch output cannot replace the assistant answer. Recovery uses the persisted terminal receipt without repeating native execution. Storage or journal failure before that receipt remains ambiguous, as for command and answer artifacts. Image artifacts, production delivery, public multi-turn sessions and full release certification remain unresolved.

## Generated images

The pinned Codex `imageGeneration` completion contains standard base64 image bytes in `result`. DataGround uses those bytes directly; it does not read `savedPath` or publish that path, the native item identifier, or `revisedPrompt`. The pinned source decodes the same result before saving its local copy: [`stream_events_utils.rs`](https://github.com/openai/codex/blob/4c70bff480af37b1bf1a9b352b8341060fe55755/codex-rs/core/src/stream_events_utils.rs). A completion must report `completed` and contain a nonempty valid image. Unsupported status, encoding, format, dimensions or content fails closed.

The current image profile accepts PNG, JPEG and GIF. Each image is bounded to 4 MiB, 8,192 pixels per dimension and 16,777,216 pixels in total. DataGround checks the image configuration before decoding the first image to bound allocation. Exact original bytes, including metadata and additional GIF frames, are retained; validation does not certify every animation frame. WebP, vector images and other formats are not accepted by this profile. One Codex turn admits at most 256 distinct generated images and 16 MiB of decoded image-file bytes. Exact native duplicates do not consume this budget again; a changed result under the same native identifier fails closed.

The internal `output.image.completed` snapshot goes through current authorization, readiness, lease renewal and immutable artifact finalization. The sensitive file is named `Generated image`, with its detected media type and a deterministic identity bound to the invocation and source sequence. The public `output.image.artifact` event contains only the artifact ID, digest, size, media type, width, height and a fixed summary. Persistence rejects raw snapshots and verifies the exact catalog, operation, effect and media binding before accepting the reference. Images do not replace the invocation's completed answer. The Workbench offers scoped metadata inspection and the existing separately authorized, digest-verified content download.

A native `imageView` event contains a mutable path, not the bytes presented to the model. It remains a generic activity event. Copying that path after notification would not establish an exact viewed-image snapshot. Viewed-image capture, other image formats, inline image rendering, other runtime families and production release acceptance remain unresolved.
