# Runtime message completion and invocation results

The internal adapter contract distinguishes streamed text previews from completed message snapshots. `output.text.delta` remains a display event. `output.message.completed` carries exactly `text` and `phase`, where phase is `commentary`, `final`, or `unspecified`. Text is bounded to 64 KiB. Native routing identifiers and memory-citation metadata do not cross this boundary. These events use the existing `dataground.event/v1` envelope; the new event type is additive.

The governed worker records each event through the current invocation claim before observing its result content. It selects the completed non-commentary message with the highest runtime source sequence. A later completed message replaces the prior candidate; messages are never concatenated. An unspecified phase permits the last completed answer from a runtime or model that does not classify phases. It is not relabelled as explicitly final. Commentary and text deltas remain in the event journal, but are not result candidates. Replayed source sequences do not change selection.

After successful native completion, the worker validates the selected text against the declared output schema. A text-producing turn without a completed answer fails with the existing `RUNTIME_OUTPUT_INVALID` receipt. A structured result also requires a nonempty completed answer and exactly one JSON value. A turn with no text events and no declared schema can still complete with an empty text result. The worker accepts at most 4,096 completed messages and retains its existing encoded-result limit. Invalid results cannot enter success artifact finalization. The successful attempt receipt stores the validated result, so a replacement worker can recover it without native execution. An interrupted or failed turn cannot use a completed message to bypass its terminal outcome.

The pinned Codex 0.117.0 protocol supplies authoritative text through `item/completed` with an `agentMessage` item. Its `commentary` and `final_answer` phases map to the normalized phases; null or omitted phase maps to `unspecified`. The adapter rejects malformed content, unknown phase values, foreign thread or turn scope, oversized text, and a changed completion for an already completed native item. Exact duplicates are ignored. The private completed-item ledger is bounded to 4,096 entries; identifiers are bounded to 1,024 bytes. Late item notifications cannot change a terminal turn. See the [official app-server documentation](https://learn.chatgpt.com/docs/app-server) and the [schema at the pinned source revision](https://github.com/openai/codex/blob/4c70bff480af37b1bf1a9b352b8341060fe55755/codex-rs/app-server-protocol/schema/json/v2/ItemCompletedNotification.json).

The shared adapter kit covers completed commentary, unspecified and final messages, native duplicate completion, and authoritative text that differs from its preview. Focused worker tests cover schema validation, source ordering, replay, missing answers, malformed payloads, and bounded message count. A PostgreSQL integration test covers completed-result recovery after worker replacement. The timeline displays progress messages and final answers without implying invocation success.

This remains the internal governed invocation boundary. Large-result artifact storage, invalid-result artifact retention, public multi-turn sessions, and certification of every runtime family remain separate release work. Passing these tests does not certify a runtime deployment or establish v1.0 acceptance.
