# Runtime message completion and invocation results

The internal adapter contract distinguishes streamed text previews from completed message snapshots. `output.text.delta` remains a display event. `output.message.completed` carries exactly `text` and `phase`, where phase is `commentary`, `final`, or `unspecified`. Native completed snapshots are bounded to 1 MiB of UTF-8 text. The public inline message remains bounded to 64 KiB; snapshots whose encoded payload exceeds 128 KiB also use artifact storage. Native routing identifiers and memory-citation metadata do not cross this boundary. These events use the existing `dataground.event/v1` envelope; the new event type is additive.

The governed worker records each event through the current invocation claim before observing its result content. It selects the completed non-commentary message with the highest runtime source sequence. A later completed message replaces the prior candidate; messages are never concatenated. An unspecified phase permits the last completed answer from a runtime or model that does not classify phases. It is not relabelled as explicitly final. Commentary and text deltas remain in the event journal, but are not result candidates. Replayed source sequences do not change selection.

After successful native completion, the worker validates the selected text against the declared output schema. A text-producing turn without a completed answer fails with the existing `RUNTIME_OUTPUT_INVALID` receipt. A structured result also requires a nonempty completed answer and exactly one JSON value. A turn with no text events and no declared schema can still complete with an empty text result. The worker accepts at most 4,096 completed messages and retains its existing encoded-result limit. Invalid results cannot enter success artifact finalization. The successful attempt receipt stores the validated result, so a replacement worker can recover it without native execution. An interrupted or failed turn cannot use a completed message to bypass its terminal outcome.

When a completed answer fails validation, the worker first fixes its journal source sequence, artifact identity, digest, and byte count in an `output_invalid` runtime attempt. It then checks current authorization and readiness and renews the claim. For an inline answer, it retains the exact completed text as a sensitive `text/plain; charset=utf-8` artifact named `Invalid runtime result`. For an artifact-backed answer, it reuses the exact existing catalog binding. It commits the terminal `RUNTIME_OUTPUT_INVALID` receipt only after that exact artifact has a catalog binding. This path does not export declared workspace artifacts. A missing completed answer still fails without a result artifact because no acknowledged result exists.

Object or catalog failures leave the retention intent pending. A replacement worker can adopt it under its current lease and repeat immutable finalization without starting a runtime. New runtime events cannot change the fixed source; exact event replay remains read-only. A changed source, artifact substitution, expired or stale lease, foreign domain, cancellation, or current authorization denial prevents new publication. Cancellation can leave a pending intent for operator inspection; it does not grant retention authority. Database migration 61 refuses downgrade while any pending retention intent exists. The internal source sequence is stored as a decimal string to preserve all PostgreSQL sequence values through JSON decoding. The raw result remains subject to the 1 MiB completed-snapshot limit and the deployment's artifact-size limit. An invalid result whose snapshot is already stored reuses that artifact; it does not write a second copy. Migration 62 extends pending retention to the snapshot limit and rejects downgrade while a larger pending intent exists.

Large completed snapshots are finalized as sensitive UTF-8 text artifacts under the current claim, authorization, and readiness checks. The public `output.message.artifact` event contains only `artifactId`, `digest`, `sizeBytes`, `phase`, and a UTF-8-safe preview of at most 1,024 bytes. Its artifact identity includes the isolation domain, invocation, and runtime source sequence. The journal verifies the exact catalog binding before accepting the reference. A native adapter cannot supply this event directly. Commentary artifacts remain progress only; a later completed answer replaces the earlier result candidate.

The worker validates the complete original snapshot before returning `dataground.invocation-artifact-result/v1`. This result contains `status: succeeded` and an `outputArtifact` reference with the artifact ID, digest, size, and media type. It does not return the full value inline. Completion verifies the reference against the latest non-commentary source and a successful native terminal event. A committed result survives worker replacement without repeating native execution. The Workbench exposes an inspect action after an explicit result read, and checks that the artifact belongs to the invocation before navigation. Inspection exposes artifact metadata only. Public artifact-content delivery requires a separate governed reader and is not composed yet.

Artifact publication does not establish native completion. If storage or journal acknowledgement fails before a successful runtime receipt is committed, the single-use native attempt remains ambiguous; a replacement does not rerun it. A retained artifact alone cannot prove a successful turn. Immutable finalization observes object writes before repetition, including lost write acknowledgements. This boundary does not add recovery of an unacknowledged native turn.

The pinned Codex 0.117.0 protocol supplies authoritative text through `item/completed` with an `agentMessage` item. Its `commentary` and `final_answer` phases map to the normalized phases; null or omitted phase maps to `unspecified`. The adapter rejects malformed content, unknown phase values, foreign thread or turn scope, oversized text, and a changed completion for an already completed native item. Exact duplicates are ignored. The private completed-item ledger is bounded to 4,096 entries; identifiers are bounded to 1,024 bytes. Late item notifications cannot change a terminal turn. See the [official app-server documentation](https://learn.chatgpt.com/docs/app-server) and the [schema at the pinned source revision](https://github.com/openai/codex/blob/4c70bff480af37b1bf1a9b352b8341060fe55755/codex-rs/app-server-protocol/schema/json/v2/ItemCompletedNotification.json).

The shared adapter kit covers completed commentary, unspecified and final messages, native duplicate completion, and authoritative text that differs from its preview. Focused worker tests cover schema validation, source ordering, replay, missing answers, malformed payloads, and bounded message count. PostgreSQL integration tests cover completed-result recovery, invalid-result retention after catalog outages and lost acknowledgements, immutable source binding, artifact substitution, cancellation, and stale or foreign claims. The timeline displays progress messages and final answers without implying invocation success.

This remains the internal governed invocation boundary. Public artifact-content delivery, artifact storage for large command output, diffs, and images, public multi-turn sessions, and certification of every runtime family remain separate release work. Passing these tests does not certify a runtime deployment or establish v1.0 acceptance.
