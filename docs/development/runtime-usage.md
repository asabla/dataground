# Runtime usage reporting

The invocation API's optional `usage` value is the latest runtime-reported cumulative snapshot. `inputTokens`, `outputTokens`, and `totalTokens` are non-negative integers. They are reports from the runtime, not independently verified charges or billable cost. A missing report leaves `usage` absent. It must not be presented as zero consumption.

The Codex adapter consumes `thread/tokenUsage/updated` from the pinned 0.117.0 protocol. It checks the active native thread and turn, requires both native count structures, and accepts only integer counts within JavaScript's exact integer range. It emits the three public counts from the cumulative `total` structure as `usage.recorded`; it does not add the `last` structure. Native routing identifiers, cached and reasoning breakdowns, context-window metadata, and unknown native fields are excluded. Late usage after terminal completion is ignored.

The protocol is documented in the [OpenAI app-server reference](https://learn.chatgpt.com/docs/app-server). Its exact fields are checked against the [schema at the pinned source commit](https://github.com/openai/codex/blob/4c70bff480af37b1bf1a9b352b8341060fe55755/codex-rs/app-server-protocol/schema/json/v2/ThreadTokenUsageUpdatedNotification.json). That source's `TokenUsageInfo.fill_to_context_window` can replace counts with a context-window estimate. The platform therefore preserves later corrections, including decreases, and does not infer that input plus output must equal the reported total. Counts retain their native meaning; cached and reasoning counts are not added again.

PostgreSQL validates the closed three-field payload and records the event and invocation projection in one transaction under the current invocation claim. The highest runtime source sequence selects the latest usage snapshot. An older event can enter the journal without replacing a newer projection. Exact replay returns the original event without mutation; changed replay fails. A changed latest snapshot advances the invocation's resource version. Repeated equal snapshots do not change that version. Invalid counts, unknown payload fields, wrong isolation scope, expired or stale claims, and cancellation prevent updates. If projection persistence fails, the event insert rolls back with it.

The shared adapter suite checks repeated and corrected snapshots. Native fixtures check malformed values and wrong thread or turn binding. Database tests check restart replay, source ordering, safe serialization, cancellation, stale claims, and atomic rollback. These checks establish the reporting boundary. Usage completeness, independent measurement, price conversion, budget enforcement, and accepted live conformance evidence remain separate release requirements. The checked development profile still classifies usage as unsupported for certification, with reason `NATIVE_PROTOCOL_UNCERTIFIED`, until that live evidence is incorporated.
